# 보스 AI 구조 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 보스마다 다시 쓰는 공통 FSM(큰 행동)과 Inspector에서 편집하는 패턴 선택 트리(BT), 공통 패턴 3종, 검증용 테스트 보스를 만든다.

**Architecture:** `BossFsmDefinition : FsmDefinition`이 개체별 `BossBrain`(상태 8개 + `BossBlackboard`)을 만든다. 브레인은 고를 때만 `BossPatternSelector`(한 에셋 안의 `[SerializeReference]` 노드 트리)를 평가하고, 고른 `BossPatternDefinition`의 개체별 `BossPatternRun`을 예고 → 실행 → 회복으로 진행한다. 외형은 `IBossActionState`만 읽는다.

**Tech Stack:** Unity 6000.3.23f1, C#, Unity Test Framework 1.6(NUnit), IMGUI 편집기, 기존 `ActionPlatformer.*` 어셈블리.

**Spec:** `Docs/superpowers/specs/2026-11-04-boss-ai-design.md`

**평가 규칙 (구현자가 정할 수 없는 것):**

- **Selector**: 위에서부터 처음 성공한 자식에서 멈춘다.
- **Sequence**: 자식을 모두 순서대로 통과해야 성공한다.
- **실패한 묶음**: `s.Pattern`을 자기가 실행되기 전 값으로 되돌린다.
- **WeightedRandom**
  - 각 자식을 임시 `BossSelection`으로 미리 평가해 성공한 자식만 모은다. 가중치가 0인 자식은 제외한다.
  - `Board.Random.NextDouble()`로 가중치 추첨한다.
  - 뽑힌 자식의 결과(`Pattern`)와 그 자식의 경로만 반영한다.
- **Inverter**: 자식 조건의 결과를 뒤집는다.
- **조건의 상태가 null(알 수 없음)**: 항상 실패한다. Inverter로 감싸도 실패다.
- **대상 없음**(`!HasTarget`): 거리·앞뒤·플레이어 상태 조건이 모두 실패한다.
- **잎**: `pattern`이 있고, 쿨타임이 아니고, `!UsedWithin(pattern, avoidLast)`이고, `CanStart`일 때만 성공하며 `s.Pattern = pattern`을 넣는다.
- **루트 결과**: 루트가 성공해도 `Pattern`이 null이면 `Select`는 null을 돌려준다.
- **null 자식·null 루트**: 예외 없이 실패로 처리한다.
- **쿨타임**: `RecordStart` 시 `Clock + cooldown`까지다.
- **이력**: 최근 8개를 보관한다. `UsedWithin(p, n)`은 최근 n개 안에 p가 있으면 true다.

**검증 규칙** — 오류 문자열에 노드 `Summary`를 포함한다:

- 루트가 null이면 오류.
- 묶음에 자식이 없거나 null 자식이 있으면 오류.
- 잎에 패턴이 없으면 오류.
- 거리 범위가 뒤집히면(min > max) 오류.
- Inverter의 자식이 `BossCondition`이 아니면 오류.
- 같은 노드 인스턴스가 두 번 연결되면 오류(방문 집합으로 검사).
- 깊이가 32를 넘으면 오류.
- 가중치가 음수이거나 모두 0이면 오류.
- `TryValidate`는 트리가 참조하는 패턴 정의의 `TryValidate`도 함께 부른다.

**규칙:**

- **끊는 타격**
  - `Health.InterruptVersion`이 바뀌면 이번 Tick에 소비한다.
  - 경직이 허용되는 상태: Dormant / Approach / Recover는 항상. Telegraph는 `InterruptibleDuringTelegraph`, Execute는 `InterruptibleDuringExecute`일 때. Staggered / PhaseShift / Death는 불가.
  - 허용되고 `Clock − lastStaggerAt >= staggerImmunity`(첫 경직은 항상)이면 Staggered로 간다.
  - 허용되지 않으면 버린다(나중에 경직하지 않는다).
- **Staggered**
  - 들어올 때: run `Cancel`, `Mover.Stop()`, `lastStaggerAt = Clock`.
  - `staggerDuration`이 지나고 `!Mover.IsForcedMoving && Mover.IsGrounded`이면, 대기 구간이 있으면 PhaseShift, 없으면 Approach.
- **구간**
  - 매 Tick `pending = max(pending, PhaseFor(HealthRatio))`.
  - Dormant/Approach에서 `pending > Phase`이면 바로 PhaseShift.
  - Recover와 Staggered는 끝날 때 PhaseShift를 확인한다. Telegraph/Execute는 기다린다.
- **PhaseShift**
  - 들어올 때 `Phase = pending`. 경계를 여러 개 넘었어도 한 번이다.
  - `invulnerableDuringPhaseShift`이면 `SetDamageEnabled(false)`, 나갈 때 true.
  - 끊는 타격은 소비하고 무시한다. `phaseShiftDuration` 뒤 Approach.
- **Death**
  - 들어올 때 run `Cancel`, `Mover.Stop()`.
  - `deathDuration` 뒤 `owner.gameObject.SetActive(false)`.
  - 사망은 다른 모든 처리보다 우선한다.
